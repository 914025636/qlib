## 5. 发现的问题

### 5.1 Sortino 计算口径错误（代码缺陷）

[backtest.py](../backtest.py) 第 167 行：

```python
downside = ret[ret < 0].std() * np.sqrt(MINUTES_PER_YEAR)
```

分母只对负收益子集算标准差。由于本策略 `exposure` 仅 13.4%，86.6% 的 bar 收益恒为 0：

- Sharpe 的分母是**全样本** std，被大量 0 稀释而变小
- Sortino 的分母是**负收益子集** std，不含 0，未被稀释

导致 Sortino(0.51) < Sharpe(1.84)，与常识相反。正确的下行偏差应对全样本取：

$$\sigma_{\text{down}} = \sqrt{\frac{1}{n}\sum_{t=1}^{n}\min(r_t, 0)^2}$$

低 exposure 策略下这个 bug 会被显著放大，**修复前不要参考 Sortino**。

### 5.2 年化外推放大

`annual_return` 由 60 天总收益按 `(1+total)^(1/years)-1` 外推，60 天 14.67% → 年化 129.9%，0 成本档甚至到 2404%。这类数字不具备解释力，对比不同版本时应看**总收益、Sharpe、成本/毛利**，忽略年化与 Calmar。

### 5.3 IC 量级需在真实数据上重新校准

真实 BTC 分钟级信号 IC 0.02 已属不错，本版 0.267 完全是合成数据的产物。接真实数据后若仍出现 0.1 以上的 IC，**优先怀疑数据泄漏**，重点排查：

1. orderbook 快照时间戳与 bar 边界的对齐 —— 是否用到 bar 收盘之后的盘口
2. `data.py` 中盘口重建的采样桶归属（1s 采样在分钟边界的取值）
3. 因子整体 `shift(1)` 后重跑，IC 应平滑下降而非骤降至 0

标签与切分侧本身是干净的：[labels.py](../labels.py) `_forward_return` 从 `t+execution_lag` 的 vwap 起算，`walk_forward_folds` 的 purge 已含 `execution_lag + horizon`。
